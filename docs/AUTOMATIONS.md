# HLS Aurora — automations

Add these in the HLS Aurora Grok project under Your Automations, Add.
Each block is the full prompt. Cadence is a suggestion. James picks the schedule.

## 1. Watch status

Cadence: weekday morning, or on demand.

```
CFO report for HLS Aurora (JamesTRichmond/hls-aurora).
List open PRs and their heads. Name any overlap with the wrist, living phases, dual skins, or mission.ts.
State what is on main versus only on a branch.
Name the next kindness if the wrist code is reachable, or say UNKNOWN.
Flag any risk to: no accounts, no database, localStorage-only saves, separate crew/observer components, numbers only from mission.ts.
Do not merge. Do not push. Do not change files. Report only.
```

## 2. Vision guard on a new PR

Cadence: when James asks, or after he opens or is asked to review a PR.

```
CEO and CFO review of the newest open PR on JamesTRichmond/hls-aurora.
Does it protect the dual ontology, the brass Pull, the three epistemic verbs, and the living watch?
Does it touch shared files? Are they flagged?
Did the PR body list commands and results, or claim a pass without them?
If it conflicts with SPEC.md or AGENTS.md, say so. Do not edit the vision to fit the PR.
Do not merge.
```

## 3. Next beat

Cadence: after a PR merges, or when James says the watch feels thin.

```
CEO proposes exactly one player-facing beat for HLS Aurora that deepens the dual ontology or the living watch without a new map.
CFO scopes it to one PR: files, shared files, risks, verification plan.
Do not implement unless James says to. Offer three named options and room for his own.
```

Do not add an automation that merges, force-pushes, or writes to main.
